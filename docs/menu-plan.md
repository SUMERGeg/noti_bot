# Моё меню — реализация

Утверждённое ТЗ: отдельные разделы Карточки / Рацион; внутри рациона План,
Мои блюда, Настройки. Личный каталог с КБЖУ на 100 г, категориями, избранным,
поиском, фото, описанием и ссылкой. План по датам с четырьмя приёмами пищи,
граммами, КБЖУ порций, итогами дня/приёма, обзором семи дней, переносом,
копированием приёма/дня/недели, очисткой дня. Настройки калорийного ориентира,
темы и точности чисел. Без оценки питания и расчёта ингредиентов.

Архитектура: существующие FastAPI/SQLAlchemy/vanilla JS, новые таблицы и
router /api/menu. Текущие карточки и база сохраняются без миграции их схемы.
Записи плана хранят снимок блюда: изменение/удаление каталога не портит меню.
Копирование атомарно заменяет целевой приём/день/неделю, с подтверждением UI.
Фото уменьшается в браузере и хранится как ограниченный data URL в PostgreSQL.
Суммы считаются до округления, настройка точности применяется к отображению.

Проверка: 29 серверных тестов и 3 JS-теста прошли. В браузере 390×844
проверены создание блюда, фото с уменьшением, порции 250/180 г, копирование
дня и обзор недели, сохранение темы и ориентира. Проверяющий не обнаружил
существенных ошибок. Полное БЖУ по ТЗ показывается для порции и дня;
для приёма пищи и недельного обзора достаточно суммарных калорий.

Обновление 2026-11-03: КБЖУ per100g/per_portion, необязательный вес порции,
количество grams/portions с дробями и пересчётом при известном весе. Старый
столбец menu_entries.grams хранит количество в выбранной unit; API возвращает
quantity/unit и отдельно вычисленные grams (null, если вес неизвестен).
Миграция добавочная, старые снимки считаются per100g. Копирование переносит
основу/вес/единицу/количество. 38 Python-тестов и 5 JS-тестов прошли, в браузере
проверены создание блюда на порцию, перевод 1,5 порций в 375 г и сохранение.
