# Рядом 🌿

Личный Telegram-бот с мини-приложением для карточек и напоминаний.
Название, необязательный текст, несколько времён, повторение ежедневно,
по дням недели или числам месяца. Карточки можно читать, менять и удалять.
Бот отправляет название и, при наличии текста, кнопку открытия карточки.
История выполнения и отметки в эту версию не входят.

## Посмотреть на компьютере

Нужен Python 3.12+:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
Copy-Item .env.example .env
python -m uvicorn app.main:create_app --factory --env-file .env --reload
```

Откройте [localhost:8000](http://localhost:8000). `DEV_MODE=true` включает
локальный просмотр без Telegram и без отправки. Данные сохраняются в cards.db.
Это режим разработки с открытым доступом к тестовым данным; не публикуйте его.

## Бесплатное размещение на Render

Схема: Render Free (приложение) + Supabase Free (PostgreSQL) + cron-job.org
(вызов расписания раз в минуту). Ни один платный ресурс в render.yaml не создаётся.
Аккаунты и секреты нужно настроить самостоятельно; приложение не подключено к
реальному боту, пока эти шаги не выполнены.

1. Создайте бота через [@BotFather](https://t.me/BotFather), команда `/newbot`.
   Сохраните токен в .env; не добавляйте этот файл в Git.
2. Создайте бесплатный проект на [Supabase](https://supabase.com).
   В Connect возьмите строку PostgreSQL **Session pooler**, порт **5432**
   (IPv4), подставьте пароль базы. Добавьте `?sslmode=require` (или
   `&sslmode=require`, если параметры уже есть). Пароль со спецсимволами должен
   быть URL-encoded. Это серверная строка подключения, не anon/service-role key.
   Используйте отдельный проект для этого приложения; таблица cards создаётся
   сервером с включённым RLS без клиентских политик: доступ к ней идёт только
   через наш сервер и владельца базы. Не добавляйте публичные политики.
3. Загрузите репозиторий на GitHub. В Render выберите New → Blueprint,
   подключите репозиторий с render.yaml. Либо создайте Web Service вручную:
   Python, Free, build `pip install -r requirements.txt`, start
   `uvicorn app.main:create_app --factory --host 0.0.0.0 --port $PORT`.
4. В Render Environment задайте:

   | Переменная | Значение |
   |---|---|
   | DATABASE_URL | PostgreSQL Session pooler из шага 2 |
   | BOT_TOKEN | Токен BotFather |
   | PUBLIC_URL | Полный адрес приложения, например https://ryadom-reminders.onrender.com |
   | DEV_MODE | false |
   | LOCAL_SCHEDULER | false |
   | JOB_SECRET | Случайный секрет для планировщика |
   | WEBHOOK_SECRET | Другой случайный секрет для Telegram |
   | OWNER_TELEGRAM_ID | Ваш числовой Telegram ID; 0 разрешает разных пользователей с изолированными карточками |

   Blueprint сам генерирует оба секрета. При ручном создании сгенерируйте каждый
   командой `python -c "import secrets; print(secrets.token_hex(32))"`.
   Адрес PUBLIC_URL должен совпадать с реальным адресом Render, без пути.
   Дождитесь успешного деплоя; `/health` должен возвращать `{"ok":true}`.
5. Скопируйте BOT_TOKEN, PUBLIC_URL и WEBHOOK_SECRET из Render в локальный .env
   (секрет webhook должен совпасть!). Выполните:

   ```powershell
   python -m app.setup_bot
   ```

   Команда регистрирует webhook, меню мини-приложения и команды бота. После смены
   домена или WEBHOOK_SECRET выполните её снова. Локальный .env с DEV_MODE=true
   можно оставить для просмотра: setup_bot использует только три указанных поля.
6. В [cron-job.org](https://cron-job.org/en/) создайте задание:
   - URL: `https://ВАШ-ДОМЕН.onrender.com/jobs/tick`;
   - расписание: каждую минуту;
   - метод: POST;
   - заголовок: `Authorization: Bearer ВАШ_JOB_SECRET`;
   - включите уведомления об ошибках задания.
   Используйте заголовок, не передавайте секрет в URL. Нажмите тестовый запуск:
   ожидается HTTP 200 с `sent` и `failed`. HTTP 503 означает ошибку отправки;
   следующее выполнение попробует снова. Один JOB_SECRET не даёт доступ к карточкам.
7. Отправьте боту `/start`, откройте «Мои карточки» и создайте карточку на пару
   минут вперёд. Закройте мини-приложение и проверьте получение сообщения и кнопку.
   Без `/start` бот может не иметь права написать вам.

Для личного использования рекомендуется задать OWNER_TELEGRAM_ID. Узнать ID
можно без сторонних ботов: после `/start` откройте мини-приложение и посмотрите
`Telegram.WebApp.initDataUnsafe.user.id` в инструментах разработчика Telegram
Web; это только просмотр ID, сервер проверяет подписанные initData отдельно.

## Ограничения бесплатного хостинга

[Render Free](https://render.com/docs/free) засыпает после 15 минут без входящих
запросов, может перезапускаться, имеет лимит бесплатных часов. Локальный диск
не сохраняется, поэтому SQLite в Render запрещён при запуске приложения.
Бесплатный Render Postgres истекает через 30 дней — для постоянных карточек
используется внешняя база. Регулярные вызовы cron выполняют полезную работу,
но не дают гарантий непрерывной доступности. Возможны задержки и пропуски при
сбоях/исчерпании лимитов. Проверяйте бесплатные квоты в панелях сервисов.

[Supabase Free](https://supabase.com/pricing) включает 500 МБ базы и может
приостанавливать неактивный проект после недели простоя.
[cron-job.org](https://cron-job.org/en/) поддерживает бесплатные минутные
задания. Услуги и лимиты могут измениться. Строго гарантировать доставку
лекарственного напоминания в заданную минуту на этой схеме нельзя.

Напоминания просроченные менее чем на час отправляются при следующем вызове;
более старые пропускаются, чтобы не присылать устаревшие уведомления пачкой.
Несколько пропущенных слотов одной карточки объединяются в одно уведомление.
Если Telegram принял сообщение, но ответ потерялся, повторная попытка может
дать дубль: Bot API не поддерживает ключ идемпотентности для sendMessage.
При ошибке известного результата время не сдвигается до успешной отправки.
При редактировании расписание пересчитывается от текущего времени.
31 число пропускает короткие месяцы; несуществующее время при переводе часов
пропускается, повторяющееся время срабатывает один раз.

## Проверка

```powershell
python -m pytest -q
node --check app/static/app.js
```

На постоянном сервере вместо внешнего cron можно задать LOCAL_SCHEDULER=true
(один процесс uvicorn). В Render Free используется внешний cron.
